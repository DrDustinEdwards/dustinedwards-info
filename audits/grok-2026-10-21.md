## Findings

### DE-1. An empty post listing deletes every post row, then reports success

Area: data integrity. Severity: MAJOR. Confidence: high.
File: `app/lib/operator/sync-tools.server.ts` lines 139-184. The refusal it does not use is in the same file at lines 239-246, in `app/lib/editor/publish.server.ts` lines 556-561, and in `scripts/lib/delete-floor.mjs` lines 21-26 and 44-51.

`syncPosts` loads `content/posts` and treats every D1 row whose slug is missing from that listing as unfiled. It calls `deletePostFromD1` for each one (the post row, its search documents, its `media_refs`, and a cache purge). It then reads both sides again. If the listing is still empty, the residual is zero and the tool returns `ok: true` with `converged: true`.

Every other file-to-D1 sync goes through `convergeKind`, which returns 422 when `files.length === 0`, because an empty listing would delete every row. `regenerateAllFromRepo` throws for the same reason. `scripts/sync-content.mjs` uses `requirePosts` and `deleteFloor`, which refuse zero posts and a delete that removes more than it keeps. `syncPosts` has neither check.

A GitHub error does not take this path. `gh` throws on any non-200 (`app/lib/editor/github.server.ts` lines 56-67), and `listDirectory` throws when the answer is not an array (lines 115-118). A missing directory is a 404, so it throws, and nothing is deleted. Git does not store an empty directory. The listing that wipes the table is a successful 200 whose entries include no `*.md`: a placeholder, an image, or a directory of assets only. `listPostFiles` keeps only markdown (lines 149-153). `contentDriftCompare` then marks every row unfiled.

The watchdog calls this tool with `args: {}` on content drift (`workers/watchdog.ts` lines 111-118, plan in `app/lib/health/repair.mjs`). `dei_repair_drift` calls the same plan. A 422 would stop the rest of the plan and mail "self-repair was refused". A converged empty set takes the quiet path: the recheck is healthy, and no mail goes out. The repository files are not deleted. The rendered copy is. If a later listing returns the markdown, a later `sync_posts` can rebuild the rows. If the listing stays empty of markdown, the site stays empty and the watchdog stays quiet.

There is a worker test for the empty-set refusal on procedures, dictionary, pages, publications, roster, phages, registry, CV, and llms. There is no `posts-sync` test, and no test expects `sync_posts` to refuse an empty listing.

Smallest fix: before the drift loop, if `before.files.length === 0`, return 422 with the same wording as `convergeKind`, and add the worker test the other kinds already have. Applying `deleteFloor` as well would also refuse a listing that keeps a handful of files and drops the rest.

Path: a content-drift health failure, or `POST /api/operator` with the operator token and `{"tool":"sync_posts","args":{}}`, while `content/posts` answers 200 and contains no markdown.

### DE-5. `/probe` stores request bodies with no rate limit and no size cap

Area: MCP. Severity: MINOR. Confidence: high.
Files: `mcp/src/index.ts` lines 255-257, `mcp/src/probe.ts` lines 101-148.

`/probe` is routed before the OAuth provider, on purpose, so it can watch unauthenticated clients. It does not call the operator API. A POST body that parses as JSON is stored whole. ### DE-7. `refresh_citations` will store any DOI list the operator sends

Area: data integrity. Severity: MINOR. Confidence: high.
Files: `app/lib/operator/api.server.ts` lines 571-579, `app/lib/citations.server.ts` lines 99-101 and 125-138, `mcp/src/tools.ts` lines 536-539.
